# B 端核心功能規格書 (B-Side Core Specification) v1.0

**日期**: 2026-02-12  
**狀態**: 草案 (Draft for Review)  
**目標**: 定義美業 SaaS B 端核心業務模組，確保開發前邏輯清晰，避免反覆修改。

---

## 1. 策略調整說明
鑑於「C 端預約功能」高度依賴「B 端供給數據」，本階段將暫停 C 端開發，優先完善 B 端三大核心支柱：
1.  **服務 (Services)**：定義銷售產品。
2.  **員工 (Staff)**：定義服務產能。
3.  **行事曆 (Calendar)**：定義交易與時間分配。

---

## 2. 模組規格詳細說明

### 2.1 服務項目管理 (Service Management)
> **核心價值**：建立預約的基礎單位（Item）。沒有服務，就無法預約。

*   **功能需求**：
    1.  **服務列表**：顯示所有服務項目（名稱、時長、價格、狀態）。
    2.  **新增/編輯服務**：
        *   **名稱** (必填)：如 "深層保濕護理"。
        *   **類別** (選填)：如 "臉部", "身體", "美甲"。
        *   **時長** (必填)：以分鐘為單位 (如 30, 60, 90)。
        *   **價格** (必填)：標準定價。
        *   **緩衝時間 (Buffer Time)**：服務後的整理時間（如 +10分鐘）。
    3.  **上下架管理**：可將服務標記為「停用」，不刪除歷史數據但前端不可預約。

*   **資料結構對應**：`public.services`
*   **UI 規劃**：
    *   入口：Dashboard -> 服務項目管理。
    *   介面：卡片式或表格列表，右側抽屜 (Drawer) 進行編輯。

---

### 2.2 員工與排班管理 (Staff & Availability)
> **核心價值**：管理產能 (Capacity)。確保預約不會分配給休假的員工。

*   **功能需求**：
    1.  **員工檔案**：
        *   基本資料 (姓名、電話、職稱)。
        *   **服務技能 (Skills Binding)** [關鍵]：必須明確勾選該員工「能執行哪些服務」。
            *   *邏輯*：這是 C 端預約篩選的基礎（選服務 -> 篩選員工）。
    2.  **常規排班 (Weekly Schedule)**：
        *   設定每週的工作時間模板（例：週一至週五 10:00-19:00，週六 13:00-18:00，週日休）。
    3.  **例外休假 (Time Off)**：
        *   設定特定日期的請假或公休。

*   **資料結構對應**：`public.profiles`, `public.work_schedules`, `public.staff_services` (關聯表)
*   **UI 規劃**：
    *   入口：管理 (Admin) -> 員工管理。
    *   介面：人員列表 -> 點擊進入詳情 -> 技能勾選 & 排班設定。

---

### 2.3 行事曆與預約引擎 (Calendar & Booking Engine)
> **核心價值**：系統心臟。處理時間衝突與資源分配。

*   **功能需求**：
    1.  **行事曆視圖**：
        *   **日視圖 (Daily)**：以「員工」為欄位，時間為縱軸（適合店長調度）。
        *   **月視圖 (Monthly)**：宏觀看預約密度。
    2.  **建立預約 (Create Appointment)**：
        *   **流程**：選客戶 -> 選服務 -> 選員工 (基於技能篩選) -> 系統計算可用時段 -> 確認。
        *   **衝突檢測**：系統需自動阻擋重疊時段的預約。
    3.  **預約狀態流轉**：
        *   Pending (待確認) -> Confirmed (已確認) -> Completed (已完成) / Cancelled (取消) / No Show (爽約)。
    4.  **Google Calendar 整合** (Phase 2)：
        *   雙向同步：B 端預約寫入 Google，Google 私人行程回寫佔用 B 端時段。

*   **資料結構對應**：`public.appointments`, `public.customers`
*   **UI 規劃**：
    *   入口：底部導航 -> 行事曆。
    *   介面：全螢幕日曆元件 (類似 Google Calendar 操作體驗)。

---

### 2.4 UI/UX 架構規劃 (Navigation Architecture)
> **設計原則**：高頻操作置底，低頻設定收納。

*   **底部導航列 (Bottom Navigation)** - 常駐入口 (4 Tabs)：
    1.  **首頁 (Home)**：
        *   今日看板 (Dashboard)：今日營收、預約數、待辦提醒。
    2.  **行事曆 (Calendar)** [核心高頻]：
        *   快速查看排班、新增預約。
    3.  **客戶 (Customers)** [核心高頻]：
        *   客戶列表、搜尋、CRM 歷史記錄。
    4.  **管理 (Admin)** [設定/配置]：
        *   **服務項目管理** (Services)
        *   **員工與排班管理** (Staff)
        *   **店家資訊設定** (Store Profile)
        *   **帳號設定** (My Account)
